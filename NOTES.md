## Start here (state as of 2026-11-05)

**What it is now.** A deterministic, top-down survival sim in TypeScript (browser, Canvas 2D). It began as a RimWorld-style colony sim (milestones 1-8, all done) and is turning into the player's vision (see "Design direction" below): **Project Zomboid-style survival where you control one survivor directly, with an optional colony sim** once you settle, other settlements living their own lives, and survivors with stories to hear and requests to see through. Schema version 63; 634 tests; everything pushed to origin/main.

**Run it.** `npm run dev` (the game opens on a main menu), `npm run check` (typecheck + tests: run before every commit), `npm run harness -- <name>` (balance players, a benchmark, a profiler: see harness/ and "Harness" below).

**Branch `continuous-movement` (not merged yet):** movers have precise positions; you and zombies move freely (see the session log, 2026-11-05). Merge to main once the player has tried it.

**Next, in order.**
1. **The player's playtest.** Nobody human has played since the control prototype; everything since is tested headless only. The questions it should answer: does tile-to-tile movement feel right under WASD; does combat feel right; is solo Apocalypse survivable; do talks, tasks, wishes, moodlets, resolve and the body meters add up to fun or noise.
2. Then, by what the playtest says: movement and combat feel (smooth sub-tile movement if tiles feel stiff; wind-ups, shoves, lunges); an inventory rework (weight, a backpack, containers); the visual target (isometric or top-down) and z-levels for multi-storey buildings; neighbours with more life of their own (caravans, alliances, feuds).
3. Smaller, any time: a How to play screen (left out of the menu by request); teach the solo harness to barricade, forage and hunt and re-run it; the sim in a Web Worker; compress the grid in saves; a Godot port plan (the tests are the spec).

## Project context (from initial planning)

- **Goal:** a learning and exploration project, not a shipping product. If it proves fun, port to another engine later for better platform support. Optimise for iteration speed and a good developer feedback loop.
- **Developer background:** a decade of software engineering, very little game dev (one Unity game, one simple Godot POC).
- **Game concept:** a macro-scale, 2D grid settlement survival sim. Inspirations: SimCity (emergent cities), Project Zomboid (emergent disasters), State of Decay (base and survivor management), Prison Architect and RimWorld (designation and job systems).
- **POC focus:** find or claim houses, designate rooms and their purposes (housing, mess hall, barracks, weapon storage), and either let the settlement self-organise (auto-planner) or micro-manage placement and cleanup. Each survivor has per-job-type priorities (scavenging, cleaning, zombie defence, etc.).
- **Core tension to preserve:** bigger settlement produces more, but a bigger perimeter is harder to defend. Tight fortress vs. risky expansion.

## Decisions so far

| Decision | Choice | Reasoning |
|---|---|---|
| Platform | Web | Fastest feedback loop, easy for an agent to run and inspect |
| Language / tooling | TypeScript, Vite, Vitest | Agents are strong in TS; HMR for instant feedback; headless sim tests |
| Renderer | Canvas 2D, top-down | Readability matters more than prettiness when debugging job queues. PixiJS is a possible later swap |
| Isometric / 3D | Deferred | Projection is purely a renderer concern; sim stays in grid coordinates |
| Engine (Godot etc.) | Deferred | Port later if the game earns it; the sim test suite becomes the port spec |
| Sim model | Pure, deterministic, fixed tick (default 10/sec) | Enables headless runs, replayable bugs, trivial speed controls |
| Automation model | Auto mode is a planner that emits the same designations the player does | Build manual first; auto is a layer on top, not a separate system |
| Zombies | Late milestone, crude at first | The base-building loop must be fun on its own |
| Replays | Seed + initial state + `{tick, command}[]` log | Falls out of determinism; bug reports become files |
| RNG | mulberry32, state is a single uint32 in sim state | Tiny, fast, trivially serialisable |
| Path/room invalidation | One `walkabilityVersion` counter | Simplest thing that works; refine if too coarse |
| Doors | Always walkable; act as room boundaries for flood fill | Locking/factions deferred |
| Hauling v1 | One item, one carrier, no stacks, no stockpile filters | Hauling multiplies edge cases |
| First room purposes | Housing (N beds), storage (designated area only) | Enough to exercise the requirements loop; mess hall waits for needs |
| Stuck-state thresholds | Max 600 ticks on one job; max 20 idle ticks with a doable job | Starting values, tune later |
| State mutation | Sim functions mutate the state they are given; `cloneState` (JSON round trip) when a copy is needed | Simpler than immutable updates; determinism doesn't need immutability. Replays clone the initial state first |
| Command log contents | Only commands that changed state are logged (not rejected ones, not no-ops) | Drag-painting over existing walls would otherwise flood the log; skipped entries change nothing on replay |
| View state | Camera, tool, hover, speed, pause live in `ui/view.ts`, never in sim state | Saves and replays stay free of UI concerns |
| Hot reload | `main.ts` self-accepts; on dispose it stashes sim + view state in `import.meta.hot.data` and tears down the app (RAF, listeners, HUD) | Editing any module (sim, render, ui) swaps code without losing the map you're building |
| Controls | **Select mode** (default): left-click selects a survivor (empty ground deselects), right-click moves the selected survivor. **Build mode** (B): bottom bar with categories Structure / Furniture / Rooms / Orders; 1-9 arm a tool in the open category, Tab/E and Shift+Tab/Q switch category, left-drag paints (Bresenham fills gaps), Shift = instant, right-click puts the tool down, Esc steps back (tool → build mode → selection). Always: right/middle-drag pans (a right press that moves < 4px is a click), wheel zooms at cursor, WASD/arrows pan, P priorities, Space pause, `` ` `` debug, Home recentre | Playtest feedback (2026-10-25): the flat 8-tool bar was hard to navigate. Layout and RimWorld-style select/right-click-move chosen by the player. The Move tool is gone; the first survivor is no longer auto-selected |
| Agent hooks | `window.view.tileToScreen(x, y)` and `getView()` alongside `window.game` | Lets Playwright/agents click a specific tile without camera maths |
| Movement | 4-way, `TICKS_PER_TILE = 4` (0.4s/tile at 1x). Next step starts on the same tick the previous one ends | No per-tile stutter. Confirmed by playtest: 0.4s/tile feels right, no diagonals for now |
| A* tie-breaking | Lower f, then lower h, then insertion order; neighbours N, E, S, W | Deterministic paths, needed for replays |
| Path cache | Per-survivor `path` + `pathVersion`; checked at every tile boundary, full repath on any walkability change | Simplest correct scheme. Fine for a handful of survivors; revisit with many survivors or big maps |
| Unreachable goals | Survivor drops the goal, goes idle, `note` says why | Never stuck; the debug panel answers "why is she standing there" |
| Walls on survivors | `placeWall` is rejected on a tile a survivor is on or stepping onto | Survivors can never end up inside a wall. Doors are still allowed |
| Schema version | `SimState.schemaVersion`; hot reload discards state with a different version | Milestone 2's hot state crashed milestone 3 code (`survivors` missing). Bump it whenever SimState's shape changes |
| Frame loop | Next frame is scheduled before the work; errors are caught and logged once each | One bad frame (often a half-finished edit) used to kill the loop permanently |
| Designations | Wall/Door tools place blueprints (1 wood each: haul, then build). Remove marks a wall/door; removing refunds the wood. Cancel tool (5). Shift = instant (old behaviour) | Gives hauling a purpose; instant mode kept for sandboxing |
| Build rules | Blueprints only on empty floor (to turn a wall into a door: remove, then build). Completing a wall evicts survivors and items on that tile | Simple and never traps anyone |
| Job queue | Derived from the world by `reconcileJobs` at the start of each tick: one job per blueprint (haul while it needs material, then build), one clean job per dirty tile. Invalid jobs are dropped and their worker released | Event-driven job creation would drift out of sync; a linear reconcile can't |
| Job choice | Highest-priority type first (ties: build, haul, clean), then nearest job of that type (Manhattan) that is actually doable, checking up to 8 candidates. Idle with nothing doable: retry every 5 ticks | Matches CLAUDE.md; the cap and back-off bound per-tick pathfinding cost |
| Reachability | Connected-component labels cached per grid + walkabilityVersion (WeakMap, outside sim state) | Unreachable candidates cost O(1) instead of a failed A* that floods the map |
| Default priorities | 3 / 3 / 3 for build / haul / clean | Neutral start; type order breaks ties |
| Direct orders | A move order releases the survivor's job (dropping any carried item); they go back to work after arriving | Proper drafting can come with the threat milestone |
| Dirt | 1/30 chance per step onto floor, via the sim RNG (drawn on every floor step, so RNG use doesn't depend on dirt) | Gives cleaning a steady trickle; deterministic |
| Invariant checker | `sim/invariants.ts` cross-checks survivors/jobs/items/blueprints; tests run it every tick, the debug panel shows it live | Turns "two survivors on one job" style bugs into a red test |
| Rooms | Derived by flood fill over floor (walls and doors are boundaries); regions touching the map edge are outdoors. Memoised per grid + walkabilityVersion, outside sim state | Recomputed only when walls/doors change; nothing to keep in sync |
| Room purposes | Stored as designations anchored to a tile; apply to whatever room contains the anchor. Built-over anchors slide to a neighbouring floor tile; when rooms merge the older designation wins; an anchor that ends up outdoors is kept and shows "not enclosed" | Survives remodelling (e.g. remove a wall, then build a door) without the player redoing it |
| Requirements | Both: enclosed, has a door. Housing: ≥1 bed, ≥4 tiles per bed. Storage: ≥4 tiles | Small and visible; first unmet one is shown on the room label |
| Beds | Furniture (`state.furniture`), built from a blueprint with 1 wood, walkable, items can't be dropped on them. Remove refunds the wood | Housing needs something to require; beds were due in milestone 6 anyway |
| Storage | Complete storage rooms are haul destinations: each loose item outside storage gets a store job; destination tile chosen and reserved at claim time. Builders take wood back out of storage | Answers the M4 stockpile question with the existing haul job type |
| Cleaning scope | Indoors only (any enclosed room): dirt is only tracked indoors, clean jobs only for indoor dirt | Answers the M4 home-area question; no more scrubbing the street |
| Cancel tool | On a blueprint cancels it; otherwise clears the purpose of the room under the click | One "undo a designation" tool |
| Rest and sleep | Integer rest 0-2000, drains 1/tick awake (tired below 500, ~2.5 min at 1x). Tired survivors drop their job (via releaseSurvivor), reserve the nearest reachable free bed, sleep until full. Bed +4/tick (~37s), floor +2/tick (~75s) when no free reachable bed. Survivors start at 100/85/70/55% by index (no RNG). Bed gone / path blocked → re-plan or floor, never stuck. A direct order wakes them. `setRest` debug command | Sleep first, hunger later. Integers keep it exactly deterministic; stagger avoids everyone tiring at once. Single drain rate for now (no faster drain while working) |
| Hunger and food | Food is an item (`f` in maps, tin cans on screen), stored like any item, never used for building. Satiety 0-3000 drains 1/tick always (hungry below 750, ~3.75 min at 1x). A hungry survivor with reachable free food drops their job, reserves the nearest food, walks to it and eats it in place (30 ticks, +2000). No food: keep working, look again every 20 ticks. Eat before sleeping; sleepers aren't woken to eat. Debug commands `setSatiety`, `spawnFood` | "Keep it simple at first": mirrors sleep, reuses item reservation, no mess hall or carrying food |
| Scavenging | Ruins hold crates (`c` in maps, furniture with 5 loot). The Scavenge tool (Orders, 1) drags a box; every crate with loot in it is marked. Marked crates get one scavenge job each (new job type, own priority column, tie order build > haul > scavenge > clean): search from an adjacent tile for 40 ticks, drop one find (food 60% / wood 40%, sim RNG), repeat until empty, then unmark. Finds are brought home by the existing store hauling; without storage they stay at the ruin. Cancel unmarks; Remove dismantles a crate for wood | Answers "where does food come from" with the systems already there; RNG keeps it deterministic |
| Day/night | Clock derived from the tick (nothing stored): 200 ticks/hour, 4800-tick day (8 min at 1x), start 06:00, night 21:00-05:00 with 2 h dusk/dawn fades. At night survivors go to bed below 75% rest instead of 25%. Dark overlay over the world (not survivors or labels); clock in the top bar | Sleep gets a natural rhythm; zombies will need "night" |
| Health and death | Health 0-1000. Starving (satiety 0) costs 1/tick (~100 s to die from full); +1/tick asleep, +1 per 5 ticks awake and fed. At 0 the survivor dies: job, carried item, bed and food are released, they're removed after the survivor loop (never spliced mid-iteration), and "X died of starvation/injuries" goes to the event log | Gives hunger teeth; zombies will deal damage through the same path |
| Event log | `state.events` (capped at 50), shown as a feed under the status line | Generic: deaths now, attacks later |
| End-of-tick reconcile | Room anchors and needs (beds/food) are reconciled at the end of each tick as well as the start | Work finished mid-tick (wall on an anchor, bed dismantled under a sleeper) must not leave dangling references between ticks; the fuzz test caught both |
| Zombies (M7, crude) | Night N brings 1 + N zombies (2, 3, 4, ...; was 3 + N until the player found 4 on night one too much), spread evenly through the night (night 1: 23:00, 03:00), each on an outdoor map-edge tile (sim RNG, not within 8 of a survivor); a "Night N falls: K zombies expected" notice at 21:00; at most 20 alive at once (safety cap). They walk floor only (doors stop them: CLAUDE.md door rule revised), 6 ticks/tile, chase the nearest reachable survivor (re-plan every 15 ticks), hit adjacent survivors for 40 every 10 ticks, wander when nobody is reachable, all leave at dawn. Zombie damage uses health; deaths say "died of a zombie attack" | Night pressure that rewards enclosing the base; dawn retreat keeps it crude |
| Guards | New `guard` job type, one job per zombie, first in the tie order. Guards close in and hit for 50 on arrival, then every 10 ticks (4 hits kill). Needs never pull a survivor off a guard job; nobody goes to bed with a zombie within 10 tiles; a hit wakes a sleeper | Without the guard-duty rule a tired guard flip-flopped between hunting and bed as the zombie drifted across the danger radius (the fuzz test caught it) |
| Farming | Farm area tool (Rooms, 3) lays plots on bare floor. New `farm` job type (tie order guard > build > farm > haul > scavenge > clean): stand on an empty plot to sow (20 ticks), it grows for 2400 ticks (half a day), then harvest (20 ticks) drops one food on the plot and it gets re-sown. Building a wall or door on a plot removes it; Cancel removes plots. ~4 plots per survivor keeps up; 12 plots fed 3 survivors through 3 days with surplus | Renewable food with the existing job, haul, and eat systems; outdoor fields are exposed to zombies |
| Auto-planner (M8) | `planFurnish(state, x, y)` in sim/planner.ts is pure: it returns ordinary commands plus notes, and the Furnish tool (Rooms, 4) applies them through applyCommand, so the log holds plain designateBuild commands and replays need no planner. Housing: one bed per survivor minus beds in other housing, at least 1, capped by capacity (1 per 4 tiles), existing beds/plans counted; spots are empty floor not next to a door, most walls first. Storage: nothing to add. Unfixable problems (no door, not enclosed, no purpose) are explained instead. Notes show as a 6 s message under the status line | CLAUDE.md: "the auto-planner is just another source of designations" |
| Injuries and medicine | Health tiers: above 60% normal; 30-60% hurt (5 ticks/tile instead of 4, work and guard blows at 3/4 speed); below 30% critical (drops any job, even guarding, and goes to bed, zombies or not). Sleepers stay in bed until rested *and* back to 60%, but always wake when hungry (a starving sleeper would lose health instead of healing). Bandages (`m`, a scavenge find: food 50% / wood 35% / bandage 15%) are fetched and applied by hurt survivors like a meal: +300 health, reserved so two survivors never go for the same one | Player pick from four candidate systems; makes zombie fights cost something without making them deadly |
| Wanderers | From day 2, one wanderer at 10:00 on an edge floor tile (sim RNG), a second at 14:00 only if beds outnumber survivors plus waiting wanderers. They wait in place; Take in (`acceptWanderer`) makes them a survivor with default priorities, Turn away (`dismissWanderer`) removes them; ignored for 3 hours or still there at nightfall, they leave. A wall built on one nudges them to a free neighbour (or they leave). Names come from their own counter (`namesGiven`, 26 names) so they no longer depend on entity ids | Player pick; growth is a choice, gated softly on beds |
| Weapons and armory | Weapons (`/`) are a scavenge find (food 45% / wood 30% / bandage 15% / weapon 10%). Anyone with guarding switched on and no weapon fetches the nearest free one *between jobs* (reserved like food and bandages; hunger or wounds cancel the errand). Equipped weapons sit in a separate `weapon` slot (item `carriedBy`, no `pos`), so hauling still works. Armed blows do 100 instead of 50 (2 hits per zombie instead of 4); a weapon breaks after 5 kills (`wear` on the item) and drops where its owner dies. New room purpose Armory (walls, door, 4+ tiles): weapons are hauled there if one is complete, else to storage, and move over when an armory is finished | Player pick; gives scavenging a reason to continue and guards something to gear up with |
| Mess hall | Tables (`t`, blueprint `T`, 1 wood, built like beds). Room purpose Mess hall: walls, door, at least 1 table. A seat is a free floor tile beside a table in a complete hall, one eater per seat (`meal.seat`). A hungry survivor picks the free seat nearest the food at the moment they decide to eat, carries the food there (`carrying` during a meal is allowed) and eats; no free seat, or the seat stops being one, means eating where they stand. The planner furnishes a hall with one table per 4 survivors, in the open and spaced apart | Player pick; makes room-building matter beyond beds |
| Mood | 0-100, 50 baseline, from timed thoughts (one per kind, a repeat refreshes): ate at a table +10 / without -5 (1 day), slept a full night in a bed +5 / on the floor -10 (1 day), someone died -15 (2 days), and -10 while hurt. Under 30 is miserable: work at 3/4 speed (same skip rule as hurt; both together are still 3/4). Shown as a Mood column in the priority panel, with the reasons in its tooltip and the debug panel | Crude on purpose: gives tables and beds a payoff, and deaths a cost, without a full needs model |
| Breaching | Revises "a closed building is safe". A zombie that can't reach anyone heads for the nearest survivor anyway: through doors if a survivor could walk the route, otherwise straight through walls (`'breacher'` mover: everything passable). It batters the door or wall in its way (40 per blow, every 10 ticks; doors 400, walls 1200). Damage lives in `grid.damage`, cleared whenever a tile changes. A broken structure becomes floor and leaves a blueprint to rebuild it (needs wood). Damaged structures get repair jobs (build type, no blueprint) at 2 damage per tick: half a zombie's rate, so a repairer slows a breach but can't hold a door alone | Nights were solved once you had four walls; this makes defence (guards, repairs, rebuilding) matter |
| Save and load | Game menu (≡ Game): 3 slots plus an autosave at every dawn (06:00, after the zombies leave), all in localStorage; Export save / Import file; Report bug. Formats live in `sim/savefile.ts` (pure, tested): a save is `{format, schemaVersion, state}`; a bug report is the state play started from (`handle.initial`: the scenario or the last loaded save) plus the commands since and the tick, and importing one replays it. Other schema versions are refused, not migrated. Loading pauses the game | Long games need saves; bug reports turn "it got stuck" into a file that reproduces it |
| Crafting | Workbench furniture (`k`, blueprint `K`, 1 wood; no room needed for now). New job type Craft (between Haul and Scavenge in the tie order). The player sets stock targets per craftable in the Workbench orders panel (weapon 2 wood, bandage 1 wood; default 0, max 20). While anything is below target, each bench offers one craft job: the crafter carries wood to the bench one piece at a time (`stored` on the bench, refunded if it is removed), then works 60 ticks and the item drops beside them. What gets made is decided when the wood is in: the first craftable below target. Wielded weapons don't count as stock | Wood gets a use beyond building, and weapons and bandages stop depending on scavenging luck |
| Trees | Renewable wood. Trees (`Y`) are furniture with 3 wood, marked with the Scavenge tool like crates and chopped by scavengers (wood only, no roll). They stay marked when bare and grow back one wood every 2 days. The sandbox has two groves (14 trees) | Balance pass 1: crates were the only wood source, so wood hit 0 by day 4-5 and building, crafting and rebuilding stopped for good |
| Zombie groups | From night 4 zombies arrive in groups of ceil(night / 3) on neighbouring outdoor tiles, same total per night (night 4: 2, 2, 1) | Balance pass 1: arriving singly, guards picked them off one at a time and a guarded colony never lost a door |
| Mood consequences | New thoughts: hungry (-10 while it lasts), attacked by a zombie (-10, half a day). Breakdowns: a miserable survivor (under 30) is rolled every 200 ticks (25%, sim RNG); a breakdown drops their job and blocks work for 600 ticks (needs still run), then "got it out of their system" (+15, a day) so it doesn't repeat at once. Rec room purpose (walls, door, 4+ tiles): a survivor who found no job, with mood under 70 and not relaxed today, walks to a free spot and unwinds for 200 ticks (+10, a day); a job turning up ends the visit (checked every idle-retry). New debug command `damageStructure` | Mood did nothing in balance pass 1 (never under 30); this gives low mood a cost and a remedy |
| Doctor and infirmary | New job type Doctor (second in the tie order, after Guard). A patient is a hurt survivor asleep in a bed with no treatment under way; each gets one doctor job: fetch the nearest free bandage, carry it to the bedside, 20 ticks, +300 health (same as treating yourself), and the patient sleeps through it. Infirmary purpose (walls, door, at least 1 bed): hurt survivors take its beds first and heal twice as fast there; everyone else prefers other beds. The planner furnishes one infirmary bed per 4 survivors | Medicine next steps from the injuries work: the bedridden couldn't fetch bandages for themselves |
| Bed ownership and barracks | Revises "beds first come, first served" (the milestone 6 decision; bed assignment was always planned for later). Your first ordinary bed becomes yours (`owner`); nobody else sleeps in it; a death frees it; `assignBed` gives a bed to someone (their only one; a sleeper in it moves out) or frees it. Infirmary beds are never owned. Bed choice, in order: infirmary if hurt (and not if not), your own, barracks if you guard (and not if not), nearest. Barracks purpose (as housing: beds, 4 tiles each): guards asleep in a barracks bed wake when a zombie comes within the danger radius, instead of only when hit. The planner gives every guard a barracks bed, up to capacity | Player asked for bed assignment via room types at milestone 6; light-sleeping guards make a barracks worth building |
| Zombie scaling | Each night's zombies get +20 health (night 10: 380), and each night brings one extra zombie per 4 survivors, fixed at nightfall (`zombiesTonight`). Early nights with 3 survivors are unchanged | Balance pass 2: the colony grew a survivor a day and a dozen guards mobbed each 200-health zombie; one death in 48 colony-days |
| Generated world | The game starts in a generated world (`worldgen.ts`): 128x128 by default while we develop, 64/128/256/512 on offer (`?size=N` and `?seed=N` in the URL, or the size picker by New world in the Game menu); scenarios and tests still use hand-made maps. Roads every ~64 tiles, ruined buildings in 16x16 cells near roads (walls with gaps, a door, sometimes an inner wall, crates whose loot grows with distance), forests (trees), a river and lakes (new `water` tile, impassable; bridges where roads cross), a visual ground layer, and a cleared start with an intact three-bed hut. Rooms touching water, or over 600 tiles, are outdoors | Player wanted a much larger world explored slowly |

## Design direction (2026-11-03, the player's vision)

Where the game is heading: **Project Zomboid-style survival, with world generation and an optional colony sim.**

- **Start alone.** You control one survivor directly (Zomboid-like controls) in a harsh, generated world. How harsh is a difficulty setting.
- **Meet others and form a group.** People you meet can join you. They follow you as you loot and survive, or you designate an area to settle, and the colony sim takes over there. You keep control of your own character inside the colony; everyone else runs on jobs and orders.
- **Talk to survivors.** Each has a short generated backstory (home, people, job, a regret, a pride). Talking to them gives tasks that come from it: find their old home, pet, photo or car; bury their dead or put down a turned relative; burn the place of a bad memory; clear their old street; get medicine to a friend elsewhere; call a sister's town from a radio tower. Finishing one gives lasting opinion, mood and loyalty, maybe a trait or skill. Also: survivors recognising each other, confessions that shift others' opinions, a would-be leader splitting off to found their own colony. Tasks are templates filled from world data, not hand-written branches; dialogue is a short menu (the past, skills, orders, items).
- **A living world.** Other groups and colonies exist and survive on their own: they grow, starve, trade and raid off screen, as a few numbers plus a small seed of buildings, leaders and needs (the same simulation-LOD idea as herds and dormant zombies), unfolding into real buildings and people when you get near. You can find them and help or fight them.

What already maps onto it:
- `state.harsh` is the start of difficulty presets.
- Survivors' needs, skills, traits, opinions, leader and shifts are already there.
- "Follow me" would be a job; "settle here" switches the colony sim on for an area.
- `state.settlements` already has the right shape for self-running colonies.
- The radio, points of interest, expeditions, graveyards, burning and corpses are task building blocks.

Concerns, most serious first:
1. **Movement and combat feel.** Tile-to-tile movement at 4 ticks a tile and "adjacent, hit every N ticks" won't feel like Zomboid under direct control. Probably needs smooth or sub-tile positions in the sim (or fine sub-steps), facing, vision cones, real attack timing. The control prototype decides whether the current model stretches or needs a rewrite.
2. **Tech base.** Zomboid-like play wants isometric rendering, lighting and line of sight shading, many animated characters, a real inventory UI. Pick the visual target (top-down or isometric) before investing much in rendering. The sim/renderer split keeps an engine port possible (see CLAUDE.md).
3. **Scope.** Three games in one (survival action, colony sim, living world). Grow by vertical slices: one town, an hour of fun solo survival, one recruit, one task, a small "settle here".
4. **Inventory.** One carried item per survivor and no stacks today; Zomboid needs weight, containers, a backpack, item condition. A big but contained rework.
5. **Companion behaviour.** Simple, readable orders (follow, hold here, loot this room, stay close) over clever AI.
6. **Self-running colonies** must look believable when they unfold: keep a seed of their own, not just numbers.
7. **Balance per difficulty.** Balance one "normal", derive the rest by multipliers.

Planned order:
1. A playtest of the current build (the player, first).
2. A control prototype: take over any survivor, WASD, click to attack or pick up, the camera following, their jobs off. Decides the movement and combat question.
3. A solo start, and difficulty presets.
4. Follow, hold and settle-here orders for people met.
5. Backstories, talking to survivors, the first task types (find the home, bury the dead, find the pet).
6. Self-running settlements that grow, fail, trade and fight off screen.
7. Inventory rework and the visual target, once the feel is proven.

### Decisions (2026-11-04)

1. **View.** Isometric is preferred for solo play; top-down may suit colony management. Plan for a renderer that can show both (the sim doesn't care). **Multi-storey buildings are wanted later**, so the sim needs a z-level (floor) in its coordinates before much more building code goes in. Decide this with the control prototype.
2. **Movement.** Real-time (smooth) movement is the likely end goal. Settled by the control prototype.
3. **Engine.** A desktop build is needed eventually; **Godot** is the likely target, chosen on performance and cost. Keep the TypeScript build for prototyping until the fun is proven; don't polish the Canvas renderer.
4. **Death.** If your character dies you choose: take over someone in your group, or start a new character far away in the same world. Each colonist has a **commitment** that rises and falls with how happy they are with you and the colony (food, safety, mood, opinion of you). Low commitment: they won't follow orders, leave, or can't be taken over.
5. **Win.** Endless, with optional goals. Some modes allow a cure or an escape; after either you can keep playing. Escape: arrange transport, choose to send others out ahead, then go looking for more people to bring. Escaping lands you on a new map with your gear (a new-game-plus).
6. **Time.** Days get longer so you can explore a fair while before you must rest. Actions other than walking (looting, building, crafting) scale up with the day.
7. **Control.** Both: light "group leader" orders (follow, hold, guard here, loot that) by default; the full colony tools once you settle somewhere.
8. **Map.** The player picks: island, island chain, large mainland, or a bordered map. Continuous or region-based depending on the choice.
9. **Multiplayer.** Co-op is a goal far down the line. Keep the sim deterministic (lockstep stays possible); no shortcuts that break it.
10. **Tone.** Grim, no humour. Amputation, executing prisoners, putting down turned family (rare, extreme cases; it costs heavy mood, which has its own penalties for your character).
11. **Difficulty.** Presets plus sandbox settings. Axes: weather intensity (regions of extreme heat or cold); **how far the apocalypse has progressed** (less to find, and worse condition); zombie count; nuclear winter / cloud cover (weaker crops and foliage, radioactive areas).

## Big worlds (designed for, not built yet)

The world is 256x256, but the code is shaped so it can grow towards 10,000x10,000 without rewrites:

- **Done now:** generation is a pure function of (seed, position) using a stateless hash (never the sim RNG), run chunk by chunk (32x32), with buildings that never cross a chunk border, so chunks can be generated in any order (tested). Nothing depends on the map edge (outdoors = touches water or over 600 tiles; night zombies and wanderers come from the explored frontier). Dirt and damage are index lists, not whole-map scans. Furniture has a cached tile and id index. Rendering skips off-screen and unexplored things. World zombies use simulation LOD: dormant zombies and herds are cheap markers until survivors are near.
- **Still to do for a much bigger world:** chunked storage (state still holds full-size arrays; lazy generation only decides *when* chunks are filled in), saves as seed plus changed chunks and in IndexedDB once they outgrow localStorage; a real active region (simulate only near survivors); hierarchical pathfinding (HPA*) with per-chunk walkability versions instead of the single counter; bounded room flood fill (the 600-tile cap already defines the answer, but the fill still runs to completion); spatial indexes for items and survivors; a chunk render cache and a world map. Entity ids come from `nextId`, so they depend on generation order; ids are only labels, but lazy generation should keep that in mind.
- Measured at 256x256 with a scripted player for 14 days: 0.1-0.5 ms per tick, mostly growing with the number of loose items (item lookups are still linear). Fully zoomed out the renderer holds 60 fps.

## Open questions

- **Is solo survivable for a human?** The scripted solo player died by day 2-5 (balance pass, 2026-11-04) before hand tools, foraging, hunting, longer days and group-sized nights; a human playtest is the real test. Watch food (2.4 a day to stay fed, 0.6x loot a year on), the crude starting weapon, and the hut door at night.

- **Colonies die in their first winter** (balance pass 5: days 17-19, just short of evacuation on day 20), with a scripted player that has no real defence plan. Levers: coats, siege size, food.
- **Infection may be too easy** for a player who uses herbs and amputation (balance pass 5: no infection deaths).
- **Scale: macro vs colony.** Per-survivor A* is fine for tens of people; hundreds on a big map would need hierarchical pathfinding or flow fields, an item spatial index, and an active region. See "Big worlds".
- **Residents are still simple:** they potter, trade in person, join, or fight; no caravans, scavenging runs or alliances of their own.
- **Infected rising in bed** among sleepers is brutal. Move the dying to the infirmary, or have them wake neighbours as they turn?

- **Small UI nits:** room labels overlap at low zoom; the hover checklist can cover a room's label; Remove/Cancel could use box drags.

## Dev gotchas

- **Vite's watcher can miss rapid successive edits on Windows.** Symptom: the browser keeps running old code (a `?t=` URL serves stale content) even after a page reload. Fix: re-save the file, or restart the dev server. Seen twice now (draw.ts in M3, hud.ts for the pause banner). Quick check: `fetch('/src/<file>', {cache: 'no-store'})` in the page and look for the new code. If it keeps happening, try `server.watch.usePolling` in vite.config.ts.
- **Don't fetch `/src/...` modules with made-up query strings while debugging.** Vite adds them to its module graph as separate modules with no importers, which makes hot reload fall back to full page reloads for everything they import. Restart the dev server to clear it.
- **Editing `index.html` opens a `file://` preview tab in the browser pane**, which becomes the active tab and backgrounds the game tab. Background tabs don't get `requestAnimationFrame`, so the game freezes at its current tick. Close the extra tab.
- **Stop the dev server during big multi-file sim changes** and restart it to verify. Otherwise every intermediate save is hot-reloaded and may half-apply.
- **Edits across several files are hot-reloaded one file at a time.** In-between states can throw (missing imports and so on); the frame loop now survives that. If hot reload fails outright ("Failed to reload main.ts"), refresh the page.
