- **2026-11-05, day length as one setting (time.ts, schema 61):** `settings.dayScale` (1, 2 or 3; the sandbox has a picker; Apocalypse and Nuclear winter now default to 2). A longer day stretches the clock (TICKS_PER_HOUR, DAY_LENGTH and NIGHT_TICKS are live ES module bindings) and every duration derived from it: modules register with onClock to recompute their constants (corpse rot, infection, shelf life, fuel, wounds, patience, wishes, thought lengths...). What runs at a rate per tick runs on one tick in every `scale` (slowTick): hunger, rest, thirst, crops and coops, colony work, your own timed actions. So a day holds about as many meals, sleeps and finished jobs; walking and zombies keep their pace, so a day covers more ground. tick() sets the scale from state each tick; the app sets it on load too (games load paused).
  Not scaled (small): rain filling collectors, tree regrowth timers in plain ticks.
  Trade-off of the approach: the scale is module state, not in each function's arguments. It is set from state at the start of every tick, so replays and saves stay exact, but code that reads the clock between ticks (the HUD) sees whichever world ticked last; tests reset it.
