- **2026-11-10, fast saves: written straight to text, chunks skipped by their hash as made (schema 78), bug reports from the packed state.** Saving a 512 world took ~0.5 s (the browser build: ~10 ms) and a fully explored 2048 ~9 s. Three parts, in order: the writer, a hash of each chunk as made, bug reports in the chunked form.
  - **Why / what was tried.** Measured first (new harness `save speed`: several sizes, a played state, chunked and whole saves, save and load apart, the parts on their own). Two costs: the save was built as a tree of JSON nodes (a node a tile for whole saves, a node a piece for furniture compared piece by piece), and every generated chunk was made again to compare (a 512 world's 256 chunks: ~0.4 s; 2048's 4,096: ~6 s). Fixes: `SaveWriter` writes the file with a Utf8JsonWriter (the state's members in the serializer's own order, through JsonSerializer; the grid's layers, furniture rows and the runs value by value); `WorldInfo.made` holds each generated chunk's hash as made (tiles, ground, edges, and its furniture and dormant in list order; 64 bits, `SavefileHash.cs`), so a save makes again only the chunks whose hash now differs (a played 2048: 6 of 4,096). Loading decodes run-length layers straight into the grid's lists and no longer copies the parsed tree. A bug report's start is `Savefile.bugStart` (the packed state, a world's changes only) instead of a whole copy; the game keeps that, and the report's replay plays the loaded start in place (`Replay.replayFrom`).

The file grows by the hashes, ~26 bytes a generated chunk.
  - **Decided.** The files are the old ones byte for byte but for `world.made` (checked by the new harness `save compat` on saves and bug reports written by main: they load to the identical state, and written again they're the main file plus the hashes). The hashes are made when a chunk is generated (`Worldgen.generateChunk` calls `SavefileChunks.noteMade` between making and adopting) and again on every load, from the chunks loading makes anyway (so they always match this build's generation; a schema-77 save gains them at no measurable cost). A file of an older schema loads only if its state says the same schema: `OLDEST_SCHEMA` is 77 (the old "another schema is refused" test relabels a current file as 77, and is still refused). A changed chunk is still made again at every save to find what differs (1.5-6 ms a chunk). `StateJson.Options` is made read-only at creation (the writer reads the members' order from it). A field added to Furniture still saves (rows fall back to objects, the hash to JSON), only slower.
  - **Left.** Loading is generation: every generated chunk made again (2048 fully explored: ~6 of its 7.5 s); faster chunk generation or making chunks on a worker (needs the statics in Worldplan, Heights and Time thread-safe) is the way. At 10,000 the save's 0.6 s is scanning the whole 3.6 GB grid's bare chunks for differences; the grid in chunks removes it (the save reads the grid's layers only in `Differs`, `WriteLayer` and `GridHash`, and writes them only in `unpack`). A game that has changed many chunks pays their remaking at each save; a per-session cache of made chunks would remove it.
