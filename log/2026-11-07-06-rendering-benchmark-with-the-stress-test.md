- **2026-11-07, rendering benchmark with the stress test moving (branch render-bench).** Player: benchmark rendering on the large stress test with moving entities, against TypeScript. city-1024 (about 180 colonists, 1,500 zombies) recorded by harness renderbench (the stress scenarios are now a module, harness/stressScenarios.ts). Browser: the game in a real Chrome window via Playwright (playwright-core added as a dev dependency, pre-approved; it drives the installed Chrome), 1280x720, new debug hooks window.view.loadSave / look / run / frameSamples. Godot: the same map isometric plus every mover replayed as a Sprite2D (experiments/godot-bench/stress.gd). Per frame at play zoom: browser draw 2.3 ms (p99 7.5), HUD 3.9, sim 0.6, frame 17.6 (vsync, 57 fps); Godot 2.2 ms all in (sprites 0.7, render CPU 1.3, GPU 0.15; 456 fps). Zoomed out: browser draw 5.8 ms; Godot 4.0 ms (250 fps). The browser draws only explored ground and culls off-screen movers; Godot draws everything. Read: both fit a 60 fps frame easily; Godot has far more headroom (GPU idle); the browser's HUD costs as much as its drawing on a big colony. Also seen: in the throttled browser pane the same frame measured draw 12 ms, HUD 11 ms (a slower, throttled tab). experiments/render-bench/README.md has the table.
