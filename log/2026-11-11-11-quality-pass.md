  - **For the player** (not done: each would change behaviour, a save or the design).
    - *Dead and Combat.*
      - **Two rules for how far a survivor sees at night.** `Defences.NIGHT_SIGHT` is 8 (10 on a tower) and decides which zombies a guard may hunt and a turret shoots (`Defences.seen`); `Sight.NIGHT_SIGHT` is 5 (a tower 16) and decides what a survivor sees (`Sight.sightRadius`). Same name, two values. If 8 is a deliberate "can fight what it can't quite see", rename it; if not, `seen` should ask `Sight`.
      - **A zombie's death is written three times and differs.** `Defences.springTrap` (a spike trap), the turret (Defences.cs) and `Zombies.damageZombie`: a trap kill never rolls the cure sample (`EndgameMod.maybeSample`), a turret kill does; only a blow can take a prisoner. One `killZombie(state, z, cause)` would make the differences a choice.
      - **`Shooting.forgetZombie`** (Shooting.cs) ends a guard's hunting job when the zombie is shot; every other kill leaves that to `Jobs.reconcileJobs` a tick later. Probably redundant: delete it, or do it for every kill.
      - **The walker's numbers are written twice**: `Zombies.ZOMBIE_TICKS_PER_TILE` and `ZOMBIE_DAMAGE`, and the walker's row in `ZombieKinds.VARIANTS`. The bite reads the table, wall damage and the horde's costs read the constants: change one and they part.
    - *World.*
      - **A doused tree leaves a grass scar and keeps its growth; a tree that burns out leaves a tree scar and starts again** (`FireMod.douse` against `FireMod.consume`). The renderer's comment (godot/World3D/Fires.cs) reads as if a doused tree was meant to carry the tree scar. Probably an oversight.
      - **Costs that grow with the world, not with what is near** (rule 14; none is slow today): `Noise.makeNoise` tests every active zombie for every noise (a swing makes one); `Lights.near` runs its lamp, stove, heater and car tests over the whole state before the distance test (and a stove's test scans the jobs); `Lights.loadsGenerator` builds the whole light list round each fuelled generator every tick; `Seasons.lightning` and `Orders.loot` scan all furniture or all crates.
    - *You and Core.*
      - **The day's length is a process-wide setting that only a tick sets** (`Time.setDayScale`, called from `Tick.tick`, the game's session start and `Staging.day`). A command applied before the first tick after a load, or at the start of a replay, runs at whatever scale the process last had (a 2x world loaded after a 1x one): `DAY_LENGTH`, `isNight` and `slowTick` are wrong for it. Fix: `applyCommand` and `Replay.replayFrom` set it first (free when unchanged). It changes nothing at one scale, so it was left for a decision only because it touches replays.
      - **A refused command can still change state, and refused commands are not logged**: `ControlMod.work` and `use` turn you (`c.facing`) before they can fail, and `Commands.execute` writes `s.note` before one reject. A replay does not turn you, so a later unaimed swing can go another way. Fix: set facing on success only.
      - **`talk` with nobody named picks the nearest by Manhattan distance, and `Talk.talk` then checks range by Chebyshev** (Commands.cs "talk", Talk.cs `TALK_RANGE`): someone diagonal and in range loses to someone straight ahead and out of it, and the command fails with "too far away to talk".
      - **An unknown command type throws** ("unreachable: every case returns", Commands.cs; the same in `Talk.check` for an unknown task kind) where a reject would do: an old bug report with a command since removed kills the replay.
      - **"Stop whatever this survivor is doing" is written three times with three different lists** (`Commands.dropEverything`, the expedition command inline, `Needs.killSurvivor`), and `SuccessionMod.take` (your heir) clears less than `takeControl` does: an heir who was asleep or on a job may keep it.
      - **Commands nothing sends**: `spawnVehicle` (no game code, test or harness) and `toggleDoor` (one test; the game opens doors through `use`). Removing them changes what an old log replays, so they were left.
    - *Colony and Others.*
      - **Five places take an item out of the world without `Items.removeItem`** (`state.items.splice`: Expeditions.cs, Outposts.cs twice, Settlements.cs, Visitors.cs), so they skip what it does: what a container held is not spilled and a quick slot is left pointing at nothing. A traded-away bag takes its contents with it.
      - **A survivor lost on an expedition or at an outpost leaves their bag behind in the item list, carried by nobody** (only the six worn slots are removed; `Needs.killSurvivor` drops the pack, these paths don't call it), and only the outpost path frees their bed. `Escape.carried` (new game+) also leaves the bag out.
      - **`Outposts.updateOutposts` removes an expedition from the list it is walking** (when an outpost's last member dies): the next outpost misses that dawn's finds and danger roll. `Expeditions.updateExpeditions` walks a copy.
      - **`Settlements.updateSettlements` takes a person off a settlement before it knows there is a spot for them to arrive at, and returns out of the loop if there is none**: a head lost for nothing, and the settlements after it skipped that day.
      - **The storyteller counts recent deaths by searching the event log's text for " died of "** (`Director.recentDeaths`), and the log keeps 50 entries: a busy day hides deaths from it, a reworded message breaks it, and deaths on expeditions ("was killed") never count. A list of death ticks in state would do.
      - **`JobChoice.chooseJob` says it is pure and isn't**: weighing a scout job moves the job's target (`planJob`). The stuck-state test calls it to ask a question and changes the answer.
      - **The rationing policy's text on screen says "a quarter longer"** (`Policies.POLICY_INFO`); the rule gives a third. The comment is fixed; the player-facing text was left.
      - **`Residents.attack` (hostile neighbours hitting your people) only lowers health**: no wound, no thought, no panic, where the dead's and animals' hits give all three.
    - *Day length (rules 12 and 13): several rates and durations don't follow `settings.dayScale`.* Scale 1 is right everywhere; these are wrong only at 2 or 3.
      - **`tick % N` inside a slow-tick gate.** A slow tick is a multiple of the scale, so `tick % 2` in there is always 0 at scale 2. `Seasons.cropGrows` (autumn's half rate and the nuclear winter's skip never apply at scale 2; rain always adds), `BodyMod.updateBody` (endurance, body heat, wetness: `% 4`, `% 2`, `% 3`, `% 12`), `Skills.workStep` and `toolBonus` (`% 20`, `% 4`, `% 3`). Fix: count slow ticks (`tick / Time.dayScale()`) and take the remainder of that, as `Skills` already does for one case.
      - **Durations in plain ticks**: eating, treating, reading, relaxing and a breakdown (`Food.EAT_TICKS`, `Health.TREAT_TICKS`, `Books.READ_TICKS`, `Leisure.RELAX_TICKS`, `BREAKDOWN_TICKS`) count every tick, though docs/characters.md says timed actions run on slow ticks; `Farming.EGG_EVERY` (1200) and `FurnitureMod.TREE_REGROW_TICKS` (3 x 4800, "three days") are literals.
      - **Rates outside the gate**: starving and healing (`Needs.updateHealth`), the social need (`Wellbeing`), bonds, petting the dog, the breakdown check. Whether health should follow the clock is a design question; the others look like oversights.
    - *Survivors and Items.*
      - **A hurt survivor with a job and no remedy to be had looks for one every tick** (`Needs.interruptForNeeds`: a filter over all items for each remedy kind, with no retry timer; hunger and thirst have one).
      - **Per survivor or dog, per tick, over every active zombie** (`Zombies.zombieNear` from `Needs.wantsSleep` and `wakeLightSleepers`; `Dogs.updateDogs` filters and sorts them all): the by-tile index in ZombieCrowd.cs could answer these.
      - **Two ways to name a book** ("a book on farm" in a survivor's note, `Books.describeBook`; "book on farming" in the bag, `Items.nameOf`) and **two vocabularies for resolve** (`Resolve.describeResolve`: wavering, steady; the character sheet: holding). `Health.HEALTH_LOW` and `HEALTH_CRITICAL` are both 300 and mean the same.
      - **`Inventory.NAME_SIZE` can only ever match "crowbar"** (it is read for the kind "weapon", whose only name is the crowbar), with the size the kind already has; its other rows repeat `ITEM_SIZE`. Dead data, left because it sits in the bag's layout.
    - *State, Save, Js.*
      - **`JsRecord` is a .NET `Dictionary`, which keeps insertion order only until something is removed** (a later key takes the freed slot). Rule 9 trusts it as ordered. Records that are removed from: `survivor.opinions`, `state.burnt`, `state.cleared`, `state.lightSwitches`, `state.foraged`. Nothing found today lets that order decide an outcome (the walks over them sort first or only collect keys), but the order does reach the saved JSON, and the next loop over one of these is a trap. Backing `JsRecord` with an ordered map would change the key order of existing saves' re-saves, so it is a decision.
      - **Each save writes a hash for every generated chunk (`WorldInfo.made`) and loading recomputes them all without reading the file's.** Dead weight in the file; removing it is a format change.
      - **Thirteen result types used by one test file each live in the sim** (`State/InlineTypes.cs`: `WalkToResult`, `HungryResult`, `TestBefore`... and `RngHolder`), with the test-only helpers `Js.RepoFile`, `Js.JsonParse`, `Js.Run`. Safe to move to cs/Sim.Tests; not done for want of budget.
      - **`Arena.openNear` says "the nearest open floor tile" and returns the top-left-most of the first ring that has one.**
    - *Worldgen.* Nothing wrong found in the caches (each keyed by all it depends on, none walked in an order that decides anything).
      - **Two stateless hashes in one generator**: `NatureMod.roll` (the plan, towns, roads, terrain) and `Hash.hashRoll` (lots, buildings, the start), different algorithms. Rule 11 names only the second. Merging them would change every world; a line in docs/decisions.md saying both exist on purpose would do.
