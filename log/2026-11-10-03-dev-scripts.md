- **2026-11-10, the dev scripts (check.sh builds Debug, shot.sh, finish.sh).** Agent sessions were slow: the machine loop is fast (edit + build + filtered test ~2 s, a `--shot` ~3.5 s, the check ~18 s), the time went to model round trips and traps. Three small tools remove some.
  - **The trap: Godot runs the Debug build** (`godot/.godot/mono/temp/bin/Debug`), but a plain `./check.sh` built only Release, so edit the sim, check, `--shot` showed the old code. **check.sh now also builds `godot/LoonieRoo.csproj` in Debug**, started once the Release build is done (never beside it: they share the sim's obj/) and run beside the test shards: the check takes 17-19 s before and after (1.6 s incremental). A failed Debug build makes the check red, its errors in the summary, the log `.check/build-debug.log`. With `--all` the self-test's own Debug build does it (not twice). Checked: touching a file in cs/Sim/Systems then a plain check leaves Debug/Sim.dll newer than the touch; a `#if DEBUG` error is red.
  - **shot.sh** `./shot.sh --seed=42 --start=solo --ticks=20 --shot=out.png`: builds Debug, imports the assets if the checkout has none, runs Godot with the arguments, prints only build errors, the `shot:` line and exception lines (full output `.check/shot.log`); `SHOT_TIMEOUT` (120 s); non-zero on build failure, timeout, a game exit error or no picture. Godot's working directory is `godot/`, so a relative `--shot=` or `--load=` would land there: the script makes them absolute from where it was run.
  - **finish.sh** `./finish.sh [--all] "message"` or `-F file`: refuses with nothing to commit; runs the check; on red commits nothing and exits 1; on green `git add -A`, prints what was staged, commits (never pushes), prints the hash and subject, and warns if the commit has no new `log/` entry. `log/_template.md` is the shape of an entry (the `_` sorts it apart from the dated ones).
